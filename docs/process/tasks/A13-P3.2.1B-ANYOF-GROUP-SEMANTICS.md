## Original behavior

`parse_contract_targets` only extracted `SingleTargetRequirement` blocks and silently ignored `AnyOfRequirement` candidates.

`check_batch` compared production hook targets to the flat set of single contract targets, so any `AnyOfRequirement` group was completely invisible.

A contract `AnyOfRequirement` with two or more candidates produced no parity diagnostics, regardless of whether production matched any candidate.

## Invariants

Behavior that must remain unchanged:

- `SingleTargetRequirement` parsing, duplicate detection, JVM type normalization, overload signature set comparison, disjoint mismatch/orphan diagnostics, unresolved parameter type reporting, and criticality checks.

Behavior that must change:

- `AnyOfRequirement` groups must be parsed as a unit.
- At least one matching candidate must satisfy the group.
- Group criticality (`REQUIRED`/`OPTIONAL`) must participate in parity checks.
- Candidate parameter types must participate in matching.

Forbidden behavior:

- Flattening `AnyOfRequirement` candidates into independent required `SingleTargetRequirement` entries.
- Ignoring candidate parameter types.
- Downgrading a `REQUIRED` group to `OPTIONAL` to suppress diagnostics.
- Silently overwriting duplicate candidates.

## Independent oracle

Main/release differential:

- Production `ModuleHelper.findAndHookMethod*` calls must match at least one candidate in each `AnyOfRequirement`.

Focused behavior test:

- `TestAnyOfRequirement` in `tools/tests/test_check_hook_contract_parity.py`.

- `parse_contract_targets` returns separate single-target map and AnyOf groups.

Mutation cases:

- ignore candidate parameterTypes;

- downgrade a required group to optional.
Each mutation must cause the corresponding test to fail.
