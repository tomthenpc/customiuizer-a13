## Original behavior

`SystemServerInstaller.install` checks:

- `MainModule.mPrefs.getInt("controls_backlong_action", 1) > 1` or
  `MainModule.mPrefs.getInt("controls_homelong_action", 1) > 1` or
  `MainModule.mPrefs.getInt("controls_menulong_action", 1) > 1`

  and directly calls `Controls.NavBarActionsHook(lpparam)`.

- `MainModule.mPrefs.getInt("controls_powerdt_action", 1) > 1` or
  `MainModule.mPrefs.getBoolean("controls_volumedowndt_torch")`

  and directly calls `Controls.PowerDoubleTapActionHook(lpparam)`.

`NavBarActionsHook` hooks `com.android.server.policy.BaseMiuiPhoneWindowManager.postKeyLongPress` and `.removeKeyLongPress` with `hookAllMethods`. Inside, it dispatches long-press Runnable actions for back/home/app-switch based on the three preference values.

`PowerDoubleTapActionHook` hooks `com.miui.server.input.util.ShortCutActionsUtils.triggerFunction` (exact `(String, String, Bundle, boolean)`) and, when `controls_volumedowndt_torch` is true, `com.android.server.policy.MiuiKeyShortcutManager.getVolumeKeyLaunchCamera` (exact no parameters) to return constant true.

## Invariants

Behavior that must remain unchanged:

- `NavBarActionsHook` hooks `postKeyLongPress` and `removeKeyLongPress` with `hookAllMethods`.
- `PowerDoubleTapActionHook` hooks `triggerFunction` with exact parameter types `(String, String, Bundle, boolean)`.
- `PowerDoubleTapActionHook` hooks `getVolumeKeyLaunchCamera` only when `controls_volumedowndt_torch` is true; its hook returns constant true.
- All activation thresholds and default values remain the same.
- Disabled path installs no hook.
- Hook method bodies, callback argument indexes, reflection calls, exception handling and fatal error rethrow are unchanged.

Behavior that must change:

- Typed `FeatureId` and `FeatureCatalog.specs()` entries must exist for `navBarActions` and `powerDoubleTapAction`.
- `DiagnosticIds` entries must exist for both.
- `CatalogContracts.navBarActions` and `CatalogContracts.powerDoubleTapAction` must describe the hook targets.
- `SystemServerInstaller` must call `FeatureDispatcher.installById("navBarActions", serverRuntime)` and `FeatureDispatcher.installById("powerDoubleTapAction", serverRuntime)` instead of the direct method calls.

Forbidden behavior:

- Leaving the legacy direct calls in `SystemServerInstaller` after migration.
- Changing the hook class/method to match the contract incorrectly.
- Adding a feature without a contract or diagnostic ID.
- Flattening `AnyOfRequirement` semantics or regressing P3.2.1A/P3.2.1B/P3.2.2 capabilities.

## Independent oracle

Main/release differential:

- The release APK uses the same `Controls` hooks when the preferences are enabled.

Focused behavior test:

- `FeatureCatalogTest` confirms `navBarActions` and `powerDoubleTapAction` are in `FeatureCatalog`, `FeatureId`, and `DiagnosticIds` with no conflicts and updated counts.
- `Batch12BehaviorTest` confirms disabled and enabled install paths, idempotency, and installer routing.

Callback/integration test:

- `SystemServerInstaller` installs both features via `FeatureDispatcher` when the corresponding preference is enabled.

Contract test:

- `CatalogContracts.navBarActions` matches `Controls.NavBarActionsHook` production calls.
- `CatalogContracts.powerDoubleTapAction` matches `Controls.PowerDoubleTapActionHook` production calls, including the optional `getVolumeKeyLaunchCamera` target.
- `tools/check_hook_contract_parity.py` continues to pass for batch 12.

ABI test:

- No change to `app/src/main/**` public API surface beyond the new catalog entries and installer dispatch.

Mutation cases:

- remove either `FeatureCatalog` spec: focused test fails;
- remove either `CatalogContracts` entry: contract parity fails;
- keep a direct `SystemServerInstaller` call and also add dispatcher: orphan direct-call path.
