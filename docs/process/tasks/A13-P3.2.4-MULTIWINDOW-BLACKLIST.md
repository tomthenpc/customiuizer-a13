## Original behavior

`SystemServerInstaller.install` checks:

- `MainModule.mPrefs.getBoolean("system_fw_splitscreen")` and directly calls `SystemFreeformAndMultiWindowHooks.MultiWindowPlusHook(lpparam)`.
- `MainModule.mPrefs.getBoolean("system_fw_noblacklist")` and directly calls `SystemFreeformAndMultiWindowHooks.NoFloatingWindowBlacklistHook(lpparam)`.

`MultiWindowPlusHook(SystemServerStartingParam)`:

- Replaces framework resources for `miui_resize_black_list` in both `android` and `com.miui.rom` packages.
- If `com.android.server.wm.ActivityTaskManagerServiceImpl` exists, hooks:
  - `updateResizeBlackList(Context)` with `DO_NOTHING`
  - `getSplitScreenBlackListFromXml()` with `DO_NOTHING`
  - `inResizeBlackList` (all methods) returning constant `false`

`NoFloatingWindowBlacklistHook(SystemServerStartingParam)`:

- Replaces framework resources for `freeform_black_list` in both `android` and `com.miui.rom` packages.
- Calls `DisableFloatingWindowBlacklistHook(lpparam.classLoader)`, which hooks:
  - `android.util.MiuiMultiWindowAdapter.getListFromCloudData` (silent)
  - `android.util.MiuiMultiWindowAdapter.getStartFromFreeformBlackListFromCloud` (silent)
  - `android.util.MiuiMultiWindowAdapter.getFreeformBlackList`
  - `android.util.MiuiMultiWindowAdapter.getFreeformBlackListFromCloud`
  - `android.util.MiuiMultiWindowAdapter.setFreeformBlackList`
  - `android.util.MiuiMultiWindowUtils.isForceResizeable`
  - `android.util.MiuiMultiWindowUtils.isPkgMainActivityResizeable` (silent)
- Hooks `com.android.server.wm.MiuiFreeformServicesUtils.supportsFreeform` to return `true`.

## Invariants

Behavior that must remain unchanged:

- `MultiWindowPlusHook` and `NoFloatingWindowBlacklistHook` implementation logic and callback bodies are unchanged.
- `MultiWindowPlusHook(PackageReadyParam)` for `com.miui.home` continues to be called directly by `LauncherInstaller`; it is out of scope for this slice.
- Resource replacement calls (`setResReplacement`) remain inside the hook bodies and are not duplicated.
- All activation thresholds and default values remain the same.
- Disabled path installs no hook.
- Hook method bodies, callback argument indexes, reflection calls, exception handling and fatal error rethrow are unchanged.
- `DisableFloatingWindowBlacklistHook` remains a private helper and is not inlined or renamed.

Behavior that must change:

- Typed `FeatureId` and `FeatureCatalog.specs()` entries must exist for `multiWindowPlus` and `noFloatingWindowBlacklist`.
- `DiagnosticIds` entries must exist for both.
- `CatalogContracts.multiWindowPlus` and `CatalogContracts.noFloatingWindowBlacklist` must describe all hook targets, including the helper targets reached through `DisableFloatingWindowBlacklistHook`.
- `SystemServerInstaller` must call `FeatureDispatcher.installById("multiWindowPlus", serverRuntime)` and `FeatureDispatcher.installById("noFloatingWindowBlacklist", serverRuntime)` instead of the direct method calls.
- `check_hook_contract_parity.py` must be enhanced so batch 12 can reconcile helper functions (e.g. `DisableFloatingWindowBlacklistHook`) without modifying hook business code.
- Feature inventory, architecture invariant counts and A13 process matrix must update from 66 to 68 catalog specs (58 to 60 adapted).

Forbidden behavior:

- Leaving the legacy direct calls in `SystemServerInstaller` after migration.
- Weakening `CatalogContracts` to only the surface target in `NoFloatingWindowBlacklistHook`.
- Adding a feature without a contract or diagnostic ID.
- Flattening `AnyOfRequirement` semantics or regressing P3.2.1A/P3.2.1B/P3.2.2/P3.2.3 capabilities.

- `CatalogContracts.noFloatingWindowBlacklist` matches `SystemFreeformAndMultiWindowHooks.NoFloatingWindowBlacklistHook(SystemServerStartingParam)` plus `DisableFloatingWindowBlacklistHook` production calls.

- No change to `app/src/main/**` public API surface beyond the new catalog entries and installer dispatch.

- remove either `FeatureCatalog` spec: focused test fails;
- remove either `CatalogContracts` entry: contract parity fails;
- keep a direct `SystemServerInstaller` call and also add dispatcher: orphan direct-call path;
- remove helper-function inlining in parity tool: `noFloatingWindowBlacklist` parity fails.
