## P1 findings from independent R3 review

1. `build_registry` AST gate 只覆盖部分 class，无法识别 alias / getattr / partial 等绕过形式。
2. completion evidence 测试仍使用手写数字作为 truth，未动态从正式文档与真实 test count 双向核对。

## Single objective

建立覆盖 `tools/tests/test_p33b_legacy_exception_routes.py` 与 `tools/tests/test_legacy_exception_source_contract.py` 的统一 AST gate，仅 `P3_3B_GeneratorConsistencyTest` 允许引用 `build_registry`；重写 `test_p33b_completion_evidence.py` 为动态 loader + 正式文档数字核对；补齐 P2 parser 边界 subtests。

## AST gate policy

- 扫描完整模块，自动覆盖现有及未来所有 `unittest.TestCase` 子类。
- 唯一 allowlist：`P3_3B_GeneratorConsistencyTest`。
- 必须识别并拒绝：
  - `build_registry(...)`
  - `builder.build_registry(...)`
  - `import tools.build_legacy_exception_registry as reg; reg.build_registry(...)`
  - `from tools.build_legacy_exception_registry import build_registry as br; br(...)`
  - `fn = builder.build_registry; fn(...)`
  - `getattr(builder, "build_registry")(...)`
  - `functools.partial(builder.build_registry, ...)` / callback alias
  - `lambda: builder.build_registry(...)` / `some_call(builder.build_registry)`
- 不得误报 docstring、注释、字符串、非精确名称、`builder.validate`、`builder.canonical_diff`、`builder.LEGACY_EXCEPTION_SEEDS`。

## Completion evidence truth model

- 实际测试数量由 `unittest.defaultTestLoader` 在运行时机械计算。
- 正式文档数量从 `TASK_STATE.md`、`SMART_OPERATION_STATE.md`、R3/R4 handoff 与 task slice 的 active section 提取。
- 核心比较：`actual == doc_counts`。
- 不得在手写源码中保留任何测试数量。
