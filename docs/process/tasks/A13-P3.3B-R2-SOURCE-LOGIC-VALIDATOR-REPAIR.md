## Source parser design

新增 `tools/legacy_exception_source_contract.py`（只读）：

- `extract_function_body(text, func_name, language)`：使用 balanced-brace 从 Java/Kotlin 源码精确提取函数体，不依赖文件内 token 搜索。
- `extract_balanced_range(text, start)`：带字符串/注释感知的 brace 计数器。
- `find_top_level_returns(body)`：提取不位于嵌套 block 内的顶层 `return <expr>;`。
- `extract_if_blocks(body)`：提取所有顶层 `if (condition) { ... }` 的条件与 block 体。
- `parse_boolean_expression(expr)`：把加括号的布尔表达式拆分为顶层操作数与顶层 `&&`/`||` 运算符，支持嵌套括号与字符串字面量。
- `find_hook_calls_in_block(block)`：识别 `ModuleHelper.hookAllConstructors`/`hookAllMethods`/`findAndHookMethod` 等 Hook 调用，返回目标类名与方法签名。
- `get_enclosing_if_condition(source_text, call_str)`：定位某条调用语句被哪个 `if` 条件包裹，返回条件表达式字符串。
- `derive_setup_global_actions_activation()`：从 `SystemServerInstaller.needGlobalActions()` 推导激活契约。
- `derive_setup_foreground_monitor_activation()`：从 `SystemUiInstaller.install()` 推导 record 激活契约。
- `derive_setup_foreground_monitor_call_site_conditions()`：从 `GlobalActions.setupForegroundMonitor()` 推导每个 Hook call 的 call-site 条件。

不使用第三方 parser，不引入新依赖。

### needGlobalActions 结构化证明

#### 函数边界

- 精确提取 `static boolean needGlobalActions()` 的函数体。
- 确认 body 从 `static boolean needGlobalActions()` 开始、对应 closing brace 结束、不包含后续 `rethrowIfFatal()`。
- 抵抗文件内其他 `_action` token。

#### 分支 A（动态 action）

确认同一逻辑链中存在：

```text
key != null
&& key.endsWith("_action")
&& value instanceof Integer
&& (Integer) value > 1
```

- 顶层运算符全为 `&&`。
- 删除任一条件、改变 suffix、改变 `Integer` 类型、threshold 改为 `0` 或 `2` 都失败。

#### 分支 B（media/app-set）

确认 return expression 为：

```text
(controls_volumemedia_up > 0 || controls_volumemedia_down > 0)
&& !controls_mediaplayer_apps.isEmpty()
```

- up/down 之间为 `||`。
- media group 与 app-set 非空之间为 `&&`。
- app-set 非空检查位于同一 return expression。
- app-set 使用逻辑取反。
- 两个 int threshold 均为 `0`。

以下 mutation 必须失败：

- media OR -> AND
- media/app-set AND -> OR
- 删除 up
- 删除 down
- 删除 app-set
- 删除 `!`
- `isEmpty()` 改成相反语义
- threshold 0 -> 1
- app-set 检查移动到函数内无关位置

## Validator fail-closed

修改 `tools/build_legacy_exception_registry.py`。

### activationContract 类型

任何 `.get()` 之前先检查：

```text
isinstance(activation_contract, dict)
```

非 dict 时返回：

```text
INVALID_ACTIVATION_CONTRACT: activationContract must be an object
```

不得抛出 `AttributeError`/`TypeError`/`KeyError`。

### thresholdExclusive 类型

对 `INT_KEY_GT`/`DYNAMIC_SUFFIX_INT_GT`/`FIXED_INT_ANY_GT_AND_NONEMPTY_SET` 强制：

```python
def is_strict_int(value):
    return isinstance(value, int) and not isinstance(value, bool)
```

- 必须拒绝 `bool`、`string`、`float`、`null`、`list`、`object`。
- 错误码：`INVALID_ACTIVATION_THRESHOLD`。

### activation schema strictness

每个 mode/kind 使用精确 allowed/required field set。拒绝：

- 缺 required field
- 未知字段
- unknown mode
- unknown kind
- empty predicates
- duplicate predicates
- empty/duplicate `integerKeys`
- `UNCONDITIONAL` 携带 predicates
- 空 `key`/`keySuffix`
- 非 canonical 排序
- 非 string key

### callSiteConditions 分支约束

每个 call-site condition predicate 必须与 record-level `activationContract.predicates` 中的一个 predicate canonical 完全相等。否则：

```text
CALL_SITE_CONDITION_NOT_ACTIVATION_BRANCH
```

## Schema v4 / runtimeConfigKeys

升级 schema version：`3 -> 4`。

新增可选 record 字段：

```text
runtimeConfigKeys
```

定义：

- `preferenceKeys`：该 record 引用的全部固定 literal preference keys。
- `activationContract`：控制 entrypoint 是否被安装的机器条件。
- `callSiteConditions`：entrypoint 内特定 Hook call 的附加安装条件。
- `runtimeConfigKeys`：功能安装后在 Hook/observer 回调中读取、但不作为 installer activation 的固定配置 key。

### 双向不变量

```text
fixedActivationKeys = activationContract 中所有固定 key ∪ integerKeys ∪ requiredNonEmptySetKey
callConditionKeys = callSiteConditions 中所有固定 key
runtimeKeys = runtimeConfigKeys
preferenceKeys == sorted(fixedActivationKeys ∪ callConditionKeys ∪ runtimeKeys)
```

拒绝：

- activation 固定 key 未进入 `preferenceKeys`
- condition key 未进入 `preferenceKeys`
- runtime key 未进入 `preferenceKeys`
- `preferenceKeys` 存在无法归类的额外 key
- dynamic suffix domain 被枚举进 `preferenceKeys`
- `runtimeConfigKeys` 与 activation fixed keys 重复
- `runtimeConfigKeys` 与 call condition keys 重复
- `runtimeConfigKeys` 为空字符串或重复
- `runtimeConfigKeys` 非 list
