## reasonCode selection

- `setupGlobalActions`：`LIFECYCLE_BOOTSTRAP`。该 entrypoint 在 `SYSTEM_SERVER_STARTING` 阶段安装，必须钩住 `AccessibilityManagerService` 构造函数和 `BaseMiuiPhoneWindowManager#initInternal` 才能在整个系统生命周期中接收/分发全局 broadcast action。当前无法拆分为单一 typed Feature，因为一个 `setupGlobalActions` 内部注册了跨多个 action 的 broadcast receiver，涉及多个 ROM-specific 系统服务类。
- `setupStatusBar`：`CROSS_PROCESS`。status-bar receiver 在 SystemUI `PACKAGE_READY` 阶段注册，响应来自其他进程（controls、launcher、system）发送的有序广播，并执行 SystemUI-only 操作（expand notifications、toggle GPS 等）。
- `setupForegroundMonitor`：`CROSS_PROCESS`。该 entrypoint 监听 SystemUI 内部 foreground activity 变化，并通过 `Settings.Global` 将 foreground package/fullscreen 状态写入全局设置，供 system_server / other modules 读取。
- `AlarmCompatServiceHook`：`LIFECYCLE_BOOTSTRAP`。该 hook 依赖 `AlarmManagerService#onBootPhase(500)` 生命周期才能安全注册 ContentObserver；目标类 `com.android.server.alarm.AlarmManagerService` 是 ROM/AOSP 混合实现，当前无法以 typed Feature 表达。

## Schema evolution

从 P3.3A schema 升级到 schema version 2，再由 P3.3B-R1 升级到 schema version 3：

- v2：保留 `firstBatchSize` 并始终等于 4（P3.3A 记录数）；新增 `registeredRecordCount`、`batchCounts`、每条 record `batch` 字段；canonical comparison 覆盖所有新 top-level 字段和 records 全字段；`--check` 在 batch 被删除/修改/移动时报告 stale；不降低 P3.3A-R1 的 stale/whole-file/all-legacy/path gates。

## Exit conditions

- `GlobalActions.setupGlobalActions`：当每个 global action 都有独立的 typed FeatureSpec，且 system_server/SystemUI/launcher 各进程分别通过 typed dispatcher 安装并声明跨进程 broadcast contract 后，可移除该 exception。
- `GlobalActions.setupStatusBar`：当 status-bar 全局 action receiver 被迁移为 typed SystemUI FeatureSpec，并声明 `CentralSurfacesImpl#start` hook 与 cross-process broadcast contract 后，可移除。
- `GlobalActions.setupForegroundMonitor`：当 foreground package/fullscreen 监控被迁移为 typed SystemUI FeatureSpec，并显式拥有 `NetworkSpeedController`、`MiuiActivityUtil`、`StatusBarStateControllerImpl` 生命周期后，可移除。
- `AlarmCompatServiceHook`：当 alarm 兼容逻辑被迁移为 typed system_server FeatureSpec，并声明 `AlarmManagerService` 生命周期与 per-app allowlist contract 后，可移除。
