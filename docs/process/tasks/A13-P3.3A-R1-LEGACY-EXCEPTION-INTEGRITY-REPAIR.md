## Stale registry判定规则

1. `python tools/build_legacy_exception_registry.py --check` 必须从当前 `FIRST_BATCH_SEEDS` 与当前 `scan_legacy_call_sites()` 重建 expected registry。
2. expected 与 committed registry 做结构化 canonical 深比较。
3. 比较时排除 `generatedAt`、`sourceCommit`、易变 provenance 字段。
4. 比较至少包括：
   - `schemaVersion`
   - `inputDigest`
   - `totalLegacyCallSites`
   - `totalLegacyGroups`
   - `firstBatchSize`
   - records 的完整字段（id、status、owner、sourceFile、entrypoint、process、phase、preferenceKeys、reasonCode、reason、coveredCallSites、hookTargets、testEvidence、exitCondition）
5. 以下变化必须导致非零退出：
   - 删除一个 seed
   - 修改 seed owner
   - 修改 seed `ownedFunctions`
   - 修改 process/phase/reasonCode
   - 修改 hookTargets
   - 修改 testEvidence
   - 修改 exitCondition
   - 增加新的 seed
6. 错误输出必须指出具体字段、record ID、缺失/新增项，不能仅输出 “registry stale”。

## Whole-file / all-legacy 防滥用规则

1. 不依赖硬编码文件名、硬编码 `54`、`SystemUIControlCenterHooks.kt` 或当前数量 `514`。
2. Whole-file 判定：对每条 record，按当前 census 计算其 `sourceFile` 的全部 `LEGACY_EXCEPTION` call sites 与全部 legacy functions；若该 record 的 `coveredCallSites` 等于该文件全部 legacy call sites，或该 record 涉及的 function 集合等于该文件全部 legacy functions，则拒绝。
3. All-legacy 判定：计算当前全部 `LEGACY_EXCEPTION` call sites 与本批 records 的 `coveredCallSites` 并集；若并集等于全部 legacy call sites，则拒绝。
4. Mixed typed/legacy 文件适用同样的动态规则，不特判。

## Path normalization 规则

1. 建立独立 helper `validate_repo_relative_posix_path(...)`。
2. 拒绝：
   - Windows 反斜杠 `\`
   - 混合 `/` 与 `\`
   - 绝对路径（以 `/` 开头、Windows 盘符、UNC）
   - `./`、`../`、路径遍历
   - 重复分隔符 `//`
   - 规范化前后不一致
   - `SOURCE_ROOT` 之外的指向
3. 合法示例：`tv/withaibuild/customiuizer/mods/SystemSettingsMoreHooks.kt`。
4. 在 Windows 与 Linux 下行为一致，不依赖 Windows `Path.exists()` 解析反斜杠作为合法性判据。

## Provenance 设计

- `schemaVersion`: 固定为 1。
- `sourceTree`: 生成时扫描输入源码对应的 Git tree SHA（`HEAD:app/src/main/java`），作为信息字段，不参与 canonical stale 比较。
- `generatorVersion`: 生成器脚本的稳定摘要，作为信息字段。
- `inputDigest`: SHA-256 of sorted current `LEGACY_EXCEPTION` call IDs，作为 canonical provenance 参与 stale 比较。
- `sourceCommit`: 被扫描输入的基线 commit（`HEAD`），作为信息字段，不参与 canonical 比较；它**不**表示“包含 registry 的最终 commit”，避免自引用。
- `generatedAt`: 仅信息字段，不参与 canonical 比较。
- `totalLegacyCallSites` / `totalLegacyGroups` / `firstBatchSize`: 参与 canonical 比较。

`--build` 输出必须稳定排序；同样输入重复执行，除 `generatedAt` 外 canonical 内容一致。
