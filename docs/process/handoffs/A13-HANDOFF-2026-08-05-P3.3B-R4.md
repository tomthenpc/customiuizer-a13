## 3. Key implementation

### 3.1 Unified AST gate

- 新增 `tools/tests/p33b_ast_policy.py`，统一扫描 `test_p33b_legacy_exception_routes.py` 与 `test_legacy_exception_source_contract.py` 完整模块。
- 唯一允许调用 `build_registry` 的 class 是 `P3_3B_GeneratorConsistencyTest`；该模块内其他所有 class、lambda、helper 均被禁止。
- 识别并拒绝：直接调用、module attribute、import alias、module alias、assignment alias、`getattr(..., "build_registry")`、`functools.partial(builder.build_registry, ...)`、callback 引用、嵌套 lambda/参数引用。
- 通过 AST parent map 与 class context 自动覆盖未来新增的所有 TestCase，默认禁止。

### 3.2 Dynamic completion evidence

- `test_p33b_completion_evidence.py` 使用 `unittest.defaultTestLoader` 在运行时机械计算 focused counts 与 discover total。
- 与 `TASK_STATE.md`、`SMART_OPERATION_STATE.md`、R3/R4 handoff 与 task slice 的 active verification 段直接比较：
  - 每个 required metric 必须存在；
  - 同一 active section 不得出现重复冲突数字；
  - `N/M pass` 必须 `N == M`；
  - 数字必须为整数；
  - 历史说明中的旧数字不会被错误识别为 active evidence。
- 不再保留任何手写测试数量作为 truth 或 fallback。

### 3.3 P2 parser boundaries

- 在 `test_legacy_exception_source_contract.py` 中以 subTest 覆盖：
  - 多行 Java declaration；
  - annotation + generic return declaration；
  - Kotlin 多 modifier + return-type block-body declaration；
  - Kotlin expression body 明确 fail-closed；
  - 注释/字符串中的 `if (...) {}` 与 braces；
  - 相邻函数包含完整伪 activation；
  - 目标函数前无分号 Kotlin invocation；
  - anonymous object 内同名函数 overload 检测。
- 在 `legacy_exception_source_contract.py` 中最小修复 Kotlin return-type 跳过逻辑，保持 fail-closed，未扩展为通用 parser。
