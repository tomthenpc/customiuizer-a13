关键修复
--------

1. LP extent 原始文件偏移

   旧实现：
       raw_offset = (first_logical_sector + target_data) * 512
   错误原因：first_logical_sector 是 target device 元数据，不属于 raw super.img
   文件偏移。

   新实现：
       raw_offset = target_data * 512
       target_device_relative_offset = (target_data - first_logical_sector) * 512

   对 HyperOS veux 的 product_a 示例：
       first_logical_sector = 2048
       target_data          = 6144
       raw_offset           = 6144 * 512 = 3145728

   该修复已加入 `tools/rom_super_inspector.py`，并保留 `target_device_first_logical_sector`
   与 `start_bytes_on_target_device` 两个独立字段供审计。

2. 文件系统魔数

   EROFS 魔数修正为 little-endian 字节 e2 e1 f5 e0（magic 0xE0F5E1E2）。
   探测位置与结果：
   - EROFS：offset 1024
   - ext4：offset 1024（superblock）+ 56 = 1080，magic 0xEF53
   - F2FS：offset 1024
   - SquashFS：offset 0
   - UNKNOWN：未命中任何已知签名

3. 分区名规范化

   修复 liblp 返回 name 含尾部 NUL 字节导致的断言失败：
       name = part.name.decode("utf-8", "replace").rstrip("\x00")

Issue #3 静态证据
-----------------

目标：Extended notification menu（pref_key_system_notifrowmenu）
Installer：SystemUiInstaller.java:127
Hook：     SystemNotificationMoreHooks.NotificationRowMenuHook
Target class：  com.android.systemui.statusbar.notification.row.MiuiNotificationMenuRow
Target method： createMenuViews(boolean, boolean)
JVM descriptor： (ZZ)V

HyperOS veux 提取的 MiuiSystemUI.apk DEX 证据：

- class Lcom/android/systemui/statusbar/notification/row/MiuiNotificationMenuRow; 存在
- method createMenuViews (Z Z)V 存在
- 关键字段存在：
    mContext      Landroid/content/Context;
    mMenuItems    Ljava/util/ArrayList;
    mMenuContainer Landroid/view/ViewGroup;
    mSbn          Lcom/android/systemui/statusbar/notification/ExpandedNotification;
    mParent       Lcom/android/systemui/statusbar/notification/row/ExpandableNotificationRow;
    mMenuMargin   I
- 嵌套类
    Lcom/android/systemui/statusbar/notification/row/MiuiNotificationMenuRow$MiuiNotificationMenuItem;
  存在
- 该嵌套类构造器签名：
    (Lcom/android/systemui/statusbar/notification/row/MiuiNotificationMenuRow;
     Landroid/content/Context;
     I
     Lcom/android/systemui/statusbar/notification/row/NotificationGuts$GutsContent;
     I)V

关键不匹配：

当前 r13.11.1 源码 `SystemNotificationMoreHooks.NotificationRowMenuHook` 使用：

    XposedHelpers.findConstructorBestMatch(
        menuItemClass,
        menuRowClass,
        Context::class.java,
        Int::class.javaPrimitiveType,
        Drawable::class.java,
        Int::class.javaPrimitiveType
    )

它要求第 4 个参数类型为 `android.graphics.drawable.Drawable`。
HyperOS veux 实际构造器第 4 个参数类型为
`com.android.systemui.statusbar.notification.row.NotificationGuts$GutsContent`。

因此 `findConstructorBestMatch` 在 HyperOS veux 上无法解析到该构造器，
`menuItemConstructor` 为 null，hook 的 `after` 回调会在创建菜单按钮前直接返回。
这是 Issue #3 在 HyperOS veux 上最可能的静态根因之一。


r13.10.1 制品时间线
-------------------

关键 commit（按时间顺序，从旧到新）：

- b5f92a2  chore(release): prepare r13.10.1 release candidate
           首次将 versionCode/versionName 改为 135 / r13.10.1
           此时 NotificationRowMenuHook 仍使用旧实现：
               MiuiNotificationMenuItem.constructors[0]
               向第 4 个参数传 null，无类型检查

- b58ced9  P1B-4A: reduce Notification Menu creation hot-path reflection and allocation
           开始引入 `findConstructorBestMatch(..., Drawable.class, ...)`

- 4b083b0  fix(a13): make notification menu augmentation transactional
- ecd6a95  fix(a13): correct notification row menu lifecycle and click-time binding
           继续完善 P1B-4A 重构

- 1ea342d  P1B-3 QA R3 关闭；存在历史签名 APK 版本点候选
- 570cf21  版本 135/r13.10.1 的最后一个 commit
           此时 NotificationRowMenuHook 已是 P1B-4A 重构后的实现

- 6def910  release(a13): bump version to r13.11.0

结论：

- r13.10.1 的“基线”不唯一；b5f92a2（旧实现）与 570cf21（新实现）行为不同。
- 若用户回退的 r13.10.1 是 b5f92a2 / 3dc0c1b 等 P1B-4A 之前的构建，
  则其 `constructors[0]` 逻辑可在同一 HyperOS ROM 上工作。
- 若用户回退的是 570cf21 / 1ea342d 等 P1B-4A 之后的构建，
  则同一 HyperOS ROM 上也会因构造器参数不匹配而失效。
- 用户报告的“回退 r13.10.1 恢复”暗示其实际 APK 很可能是 P1B-4A 之前的版本。
