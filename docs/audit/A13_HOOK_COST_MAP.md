## 2. 扫描方法

- 扫描路径：`app/src/main/java/tv/withaibuild/customiuizer` 下所有 `.kt` 与 `.java`。
- 识别模式：
  - Xposed Hook API：`findAndHookMethod`、`findAndHookConstructor`、`hookAllMethods`、`hookAllConstructors`、`hookMethod` 等。
  - 长期注册：`registerReceiver`、`registerContentObserver`、`postDelayed`、`addOnGlobalLayoutListener`、`GlobalScope.launch` 等。
- 进程映射（P1B-0 改进）：
  - 解析 `FeatureCatalog.kt` 中的 `FeatureSpec` 定义。
  - 解析各 `installers/*.java` 的导入以及 `ClassName.method(` 调用，建立 **方法级** installer -> mod method 映射。
  - 同一 mod 类中的不同方法可能被不同 installer 调用，因此归属到不同进程。
  - 无法确定时标记为 `unknown` 或多进程。
- 回调体解析：
  - `callback_frequency_class` 固定为 `PROCESS_STARTUP`、`COMPONENT_STARTUP`、`USER_INTERACTION`、`EVENT_DRIVEN_*`、`FRAME_OR_LAYOUT_HOT`、`UNKNOWN`。
  - `preference_read_in_callback` 固定为 `DISK_OR_IPC_READ`、`SHARED_PREFERENCES_API_READ`、`IN_MEMORY_SNAPSHOT_READ`、`CACHED_FIELD_READ`、`REGISTRATION_TIME_READ`、`UNKNOWN`。
  - `reflection_lookup_in_callback` 固定为 `CALLBACK_TIME_REFLECTION`、`PROCESS_STARTUP_REFLECTION`、`CACHED_METADATA_USE`、`UNKNOWN`。
- 稳定性：`a13_hook_cost_scan.py --verify-stability` 连续两次运行结果一致。

## 3. P1B-0 重要校正

### 3.1 进程归属校正

| 方法 | 原归属 | 校正后归属 | 依据 |
|------|--------|------------|------|
| `SystemNotificationMoreHooks.NotificationRowMenuHook` -> `MiuiNotificationMenuRow#createMenuViews` | `MULTI_PROCESS` / `SYSTEM_SERVER` | `SYSTEM_UI` | 仅 `SystemUiInstaller.install` 调用 `NotificationRowMenuHook`（`system_notifrowmenu`） |
| `GlobalActions.miuizerSettingsHook` -> `MiuiSettings#updateHeaderList` | `MULTI_PROCESS` | `SETTINGS_MAIN` | 仅 `SettingsInstaller.install` 调用 `miuizerSettingsHook` |
| `SystemNotificationMoreHooks.DisableAnyNotificationBlockHook` 等 | `MULTI_PROCESS` | `SETTINGS_MAIN` / `MULTI_PROCESS` | 由 `SettingsInstaller` 与 `SystemUiInstaller` 分别调用 |

校正后 `MULTI_PROCESS` 从 26 降至 18，`SYSTEM_UI` 从 201 升至 243，`SYSTEM_SERVER` 从 287 降至 208。

### 3.2 频率与回调分类校正

- `SystemUIApplication#onCreate`、`Application#attach`、`MiuiSettings#updateHeaderList` 等启动路径统一标记为 `PROCESS_STARTUP` 或 `COMPONENT_STARTUP`，不再标为 `HIGH` 热路径。
- `onTouch`、`onDraw`、`onLayout` 等标记为 `FRAME_OR_LAYOUT_HOT`。
- `onClick`、`onLongClick` 等标记为 `USER_INTERACTION`。
- `onReceive`、`onChange`、`handleMessage` 等标记为 `EVENT_DRIVEN_MEDIUM`/`EVENT_DRIVEN_LOW`。

### 3.3 偏好读取分类校正

- `MainModule.mPrefs`（PrefMap 内存快照）读取标记为 `IN_MEMORY_SNAPSHOT_READ`，不再与磁盘/IPC 读取同级计分。
- `Settings.System/Secure/Global`、`remote.get*()` 等标记为 `DISK_OR_IPC_READ`。

### 3.4 反射分类校正

- 回调内 `XposedHelpers.findClass`、`getDeclaredMethod`、`Class.forName` 等标记为 `CALLBACK_TIME_REFLECTION`。
- 仅使用 `ClassName.class` 的标记为 `CACHED_METADATA_USE`。

## 4. Zero-feature Enabled Cost

P1B-0 实施后 `AndroidPackageInstaller` 在 `android` 包且所有相关功能关闭时：

- 不创建 `FeatureRuntime`。
- 不调用 `FeatureDispatcher`。
- 不注册 `OnSharedPreferenceChangeListener`。
- 不加载 `SystemStatusBarAndClockHooks`、`Controls`、`SystemDisplayAndWindowHooks`（仅在对应分支触发时解析）。

功能关闭时仍存在的不可避免成本：

- `PackagePermissions`（`condition = { true }`）在 `system_server` 仍无条件注册 2 个 Hook。
- `MainModule` 入口、`PrefMap` 静态字段、`PreferenceBootstrap` 等框架级初始化为固定成本。

## 6. 限制与待确认项

1. 本扫描器无法做完整 Kotlin/Java 语义分析。动态类名、变量方法名、`hookAllConstructors` 变量目标等被标记为 `unknown`。
2. `registered_when_feature_disabled` 仅对 `FeatureCatalog` 中 `condition = { true }` 以及无条件 installer 调用给出静态判断；真实行为需运行时验证。
3. `callback_frequency_class` 基于目标方法名启发式判定，可能与实际触发频率不同。
4. 回调体提取依赖大括号匹配，部分嵌套复杂的 lambda 或 object 可能未被完整捕获。
5. P1B-0 的 `AndroidPackageInstaller` 改动带来的真实收益需 A13 真机基线确认。
