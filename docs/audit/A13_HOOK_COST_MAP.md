## 2. 扫描方法

- 扫描路径：`app/src/main/java/tv/withaibuild/customiuizer` 下所有 `.kt` 与 `.java`。
- 识别模式：
  - Xposed Hook API：`findAndHookMethod`、`findAndHookConstructor`、`hookAllMethods`、`hookAllConstructors`、`hookMethod` 等。
  - 长期注册：`registerReceiver`、`registerContentObserver`、`postDelayed`、`addOnGlobalLayoutListener`、`GlobalScope.launch` 等。
- 进程映射：
  - 解析 `FeatureCatalog.kt` 中的 `FeatureSpec` 定义。
  - 解析各 `installers/*.java` 的导入与 `ClassName.method(` 调用。

## 4. Zero-feature Enabled Cost

"模块已启用、所有相关功能关闭" 时的静态成本分析：

| 成本来源 | 是否存在 | 证据与说明 |
|----------|----------|------------|
| 模块入口执行 | 是 | `MainModule.onPackageReady` 与 `onSystemServerStarting` 先执行版本检查、偏好初始化、进程分类，然后才进入 installer 分支。 |
| 类加载 | 是 | `MainModule` 顶层 import 所有 installer；installer 按需 import 对应 mods 类。Feature 关闭时大部分类不会被主动加载，但 `GlobalActions`、`Controls`、`Various` 等多进程复用类会被加载。 |
| 静态初始化 | 部分 | `MainModule.mPrefs = new PrefMap<>()` 无条件发生。`object FeatureCatalog`、`FeatureInstallRegistry` 等 singleton 会在 `FeatureDispatcher` 初始化时触发。 |
| 偏好读取 | 是 | `MainModule` 调用 `PreferenceLoadRegistry.shouldLoad(remote, pkg)` 与 `initPrefs()` 在每个被 hook 进程都会发生。 |
| 功能注册器创建 | 部分 | `FeatureDispatcher.createRuntime(...)` 在 SystemUI、Launcher 等进程中被调用，但发生在门控之后。 |
| 反射查找 | 不确定 | 未启用功能的分支内反射只在对应 installer 调用后发生；但 `ModuleHelper.findContext`、`XposedHelpers.findClassIfExists` 等工具调用可能提前。 |
| Hook 注册 | 少量 | `PackagePermissions`（`condition = { true }`）无条件注册；其余由 preference 门控。 |
| Listener 注册 | 是 | `MainModule` 与 `AndroidPackageInstaller` 调用 `watchPreferenceChange`，注册偏好变化监听器。 |
| Handler/线程 | 未确认 | 未发现全局 `HandlerThread` 无条件启动。`postDelayed` 类注册点需功能触发。 |
| 日志输出 | 是 | `MainModule.onModuleLoaded` 无条件打印 `XposedHelpers.log`；各回调中仍存在日志调用。 |

可以更早返回的成本：

- `MainModule.onPackageReady` 中 `ProcessScopes.isRejected` 检查较早，可快速拒绝非 installable scope。
- 但 `getRemotePrefs()` 与 `initPrefs()` 在 rejection 检查之后调用，对于被 reject 的进程仍会读取远程偏好。

必须由框架承担的固定成本：

- LSPosed/libxposed 加载模块、调用 `onModuleLoaded`、构建 `XposedModule`。
- `PrefMap` 静态字段作为跨回调状态容器。

需要真机数据确认的成本：

- 所有 `UNKNOWN` 进程与 `SHARED` 类的实际加载时机。
- `MULTI_PROCESS` 类在各进程中的实际初始化开销。
- 零功能时 `system_server` 与 `SystemUI` 的增量 PSS。

## 6. 限制与待确认项

1. 本扫描器无法做完整 Kotlin/Java 语义分析。动态类名、变量方法名、`hookAllConstructors` 变量目标等被标记为 `unknown`。
2. `registered_when_feature_disabled` 仅对 `FeatureCatalog` 中 `condition = { true }` 以及无条件 installer 调用给出静态判断；真实行为需运行时验证。
3. `callback_frequency_class` 基于目标方法名启发式判定，可能与实际触发频率不同。
4. 回调体提取依赖大括号匹配，部分嵌套复杂的 lambda 或 object 可能未被完整捕获。
5. 部分 `MANAGER_APP` 注册点（`MainFragment`、`MainApplication` 中的 `postDelayed`）不属于 Xposed Hook，而是管理应用自身的生命周期监听；其成本应在 `manager_*` 场景下单独测量。
