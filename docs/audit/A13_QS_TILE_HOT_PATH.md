# A13 Quick Settings Tile Creation Hot-Path Cost Audit

> Branch: `devin/a13-memory-performance-optimization`
> Generated by: manual trace of `SystemUILockScreenHooks.kt` after P1B-3 optimization.

本文件记录 P1B-3 阶段对 `QSTileHost` 构造器与 `FactoryImpl#createTileInternal` 两个 Quick Settings Tile 创建热路径的调用链、修改前成本与优化后成本证据。

P0 真实设备基线仍为 `RUNTIME_BASELINE_PENDING_DEVICE`，因此任何性能收益数字均为静态推断，不声称具体 KB、MB、百分比、延迟或耗电变化。

## 1. 目标与范围

- `QSTileHost` 构造器 Hook：位于 `SystemUILockScreenHooks.SecureQSTilesHook`，在 `QSTileHost` 每个构造器调用后注册 `mAfterUnlockReceiver`。
- `FactoryImpl#createTileInternal`：位于 `SystemUILockScreenHooks.SecureQSTilesHook`（目标 `com.android.systemui.qs.tileimpl.MiuiQSFactory`），`after` 回调为每个创建的 Tile 决定是否安装 `handleClick` / `handleSecondaryClick` 保护。
- 直接使用的辅助逻辑：上述 `after` 回调动态安装的 `handleClick` `before` 回调、`handleSecondaryClick` 回调、`mAfterUnlockReceiver.onReceive`。
- 本轮不处理 `SystemUIApplication#onCreate`、通知、锁屏（除 Secure QS 自身外）、状态栏、音量面板、Launcher、第三方应用进程、UI 设置页面、签名或构建配置。
- 不新增 Tile 功能、不修改 Tile spec 名称、不修改 Tile 顺序。

所有涉及 ROM 分支判断（`ControlCenterControllerImpl` 是否存在、新旧版本状态栏类）保留在冷路径或注册阶段，不在每次 Tile 创建/点击时重复解析。

## 2. 安装与解析阶段（冷路径）

```
MainModule.onPackageLoaded (com.android.systemui)
  └─ SystemUiInstaller.install()
       └─ if (mPrefs.getBoolean("system_secureqs")) SystemUILockScreenHooks.SecureQSTilesHook(lpparam)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.qs.QSTileHost", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.qs.tileimpl.QSTileImpl", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.Dependency", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.keyguard.KeyguardViewMediator", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.statusbar.phone.CentralSurfaces", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.controlcenter.policy.ControlCenterControllerImpl", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.miui.statusbar.policy.ControlPanelController", ...)
            ├─ XposedHelpers.findClassIfExists("com.android.systemui.qs.tileimpl.MiuiQSFactory", ...)
            ├─ XposedHelpers.findFieldIfExists(...)  for mContext/mTiles/mControlCenter/.../mQSTile
            ├─ XposedHelpers.findMethodExactIfExists(...) for Dependency#get, isUseControlCenter, collapseControlCenter, postQSRunnableDismissingKeyguard, getControlCenterPanel
            ├─ ModuleHelper.hookAllConstructors(tileHostClass, hostHook)
            └─ ModuleHelper.findAndHookMethod(miuiQSFactoryClass, "createTileInternal", String::class.java, afterHook)
```

所有类/字段/方法解析一次性完成，失败时对应缓存为 `null`；回调中不再调用 `findClass` / `findField` / `findMethod`。

## 3. 修改后调用链

### 3.1 QSTileHost 构造器 after 回调

```
QSTileHost.<init>(...)
  └─ after(param)
       1. qTileHostContextField.get(param.getThisObject()) as? Context ?: return
       2. 创建 mAfterUnlockReceiver (BroadcastReceiver)
       3. ModuleHelper.registerModuleReceiver(mContext, "systemui.afterUnlockReceiver", mAfterUnlockReceiver, filter, Context.RECEIVER_EXPORTED)
```

`mAfterUnlockReceiver.onReceive` 被调用时执行：

```
1. 读 Intent extras：tileName, expandAfter, usingCenter
2. if "edit" || expandAfter：sendBroadcast(expandSettingsAction)
3. qTileHostTilesField.get(host) as? LinkedHashMap<String, Any> ?: return
4. 从 mTiles 取 tile；不存在时 if usingCenter：
   - dependencyGetMethod.invoke(null, controlPanelControllerClass) ?: return
   - mControlCenterField.get(mController)
   - mControlPanelContentViewField.get(mControlCenter)
   - getControlCenterPanelMethod.invoke(mControlPanelContentView)
   - mBigTile1/2/3 Field.get(mControlCenterPanel) per tileName
   - mQSTileField.get(mBigTile) ?: return
5. XposedHelpers.setAdditionalInstanceField(tile, "mCalledAfterUnlock", true)
6. XposedHelpers.findMethodExact(tile.javaClass, "handleClick", View::class.java)        // DYNAMIC_TILE_CLASS_REQUIRED
7. clickHandler.invoke(tile, arrayOfNulls<Any>(1))
```

> 第 6 步保留在回调中，因为 `tile.javaClass` 是运行时创建的 Tile 具体类，无法在安装阶段确定。

### 3.2 MiuiQSFactory#createTileInternal after 回调

```
MiuiQSFactory.createTileInternal(String tileName)
  └─ after(param)
       1. 取 result tile、tileClass、tileName
       2. val name = when { startsWith("intent(") -> "intent"; startsWith("custom(") -> "custom"; else -> tileName }
       3. if (!isSecureTile(name) || securedTiles.contains(tileClass)) return
       4. ModuleHelper.findAndHookMethod(tile.javaClass, "handleClick", View::class.java, tileHook)
       5. ModuleHelper.hookAllMethodsSilently(tile.javaClass, "handleSecondaryClick", tileHook)
       6. securedTiles.add(tileClass)
```

`isSecureTile(name)` 对每个 `name` 只读取一次相关 `mPrefs.getBoolean(...)`，不再构造 `HashSet`。

### 3.3 tileHook before 回调（每次 Tile 点击）

```
QSTile.handleClick(View)
  └─ before(param2)
       1. XposedHelpers.getAdditionalInstanceField(param2.getThisObject(), "mCalledAfterUnlock") as? Boolean
       2. if (mCalledAfterUnlock == true) { set false; return }
       3. val isScreenLockDisabled = if (keyguardViewMediatorClass != null) {
              XposedHelpers.getAdditionalStaticField(keyguardViewMediatorClass, "isScreenLockDisabled") as? Boolean ?: false
          } else false
       4. if (isScreenLockDisabled) return
       5. val mContext = qTileContextField.get(param2.getThisObject()) as? Context ?: return
       6. val kgMgr = mContext.getSystemService(Context.KEYGUARD_SERVICE) as? KeyguardManager ?: return
       7. if (!kgMgr.isKeyguardLocked || !kgMgr.isKeyguardSecure) return
       8. Handler(mContext.mainLooper).post { Runnable }：
            - val mStatusBar = dependencyGetMethod.invoke(null, centralSurfacesClass) ?: return@post
            - val mController = dependencyGetMethod.invoke(null, controlCenterControllerImplClass) ?: return@post
            - val usingControlCenter = isUseControlCenterMethod?.invoke(mController) as? Boolean ?: false
            - if (usingControlCenter) collapseControlCenterMethod?.invoke(mController, true)
            - val keepOpened = MainModule.mPrefs.getBoolean("system_secureqs_keepopened")    // IN_MEMORY_SNAPSHOT_READ
            - val expandAfter = usingControlCenter && keepOpened
            - val runnable = Runnable { ... sendBroadcast(handleQSTileClickAction) ... }
            - postQSRunnableDismissingKeyguardMethod?.invoke(mStatusBar, !keepOpened, runnable)
       9. param2.returnAndSkip(null)
```

回调内不再出现 `findClass` / `findField` / `findMethod`；所有反射对象已在安装阶段解析并缓存。`mPrefs.getBoolean` 仅在需要 `keepOpened` 时读取一次。

## 4. 优化后分类

| 回调 | 反射分类 | 偏好读取 | 临时分配 | 说明 |
|---|---|---|---|---|
| `QSTileHost` 构造器 `after` | `CACHED_METADATA_USE`（缓存 `Field.get`） | 无 | 每次构造新建 `BroadcastReceiver` | 与此前相同；`registerModuleReceiver` 按 key 替换，实际仍只保留一个活跃 receiver |
| `createTileInternal` `after` | `CACHED_METADATA_USE`（首次 hook 已外提） | `IN_MEMORY_SNAPSHOT_READ` x1 | 无 | `isSecureTile(name)` 单次 `getBoolean`，无 `HashSet` |
| `tileHook` `before` | `CACHED_METADATA_USE`（`Method.invoke`） | `IN_MEMORY_SNAPSHOT_READ` x1 | 每次点击新建 `Runnable`、`Intent`、参数数组 | 移除 6 次 `findClass`/`findClassIfExists`；保留必要的运行时 `Handler` / `Intent` |
| `mAfterUnlockReceiver.onReceive` | `CACHED_METADATA_USE` + `DYNAMIC_TILE_CLASS_REQUIRED`（`findMethodExact` on `tile.javaClass`） | 无 | 临时 `Intent`、`arrayOfNulls` | ROM 分支链式反射已外提；唯一运行时反射是 Tile 具体类的 `handleClick` |

## 5. 优化实施状态

### 5.1 已完成

- `QSTileHost` 构造器回调：`mContext` / `mTiles` / `mControlCenter` 链式字段 / `mBigTile1/2/3` / `mQSTile` 全部提前解析为 `Field`。
- `createTileInternal` 回调：`MiuiQSFactory` Class / Method 在安装阶段解析；`name` 归一化改用 `when`；移除 `HashSet`；增加 `isSecureTile(name)` 单次偏好读取。
- `tileHook`：所有 `Dependency` / `CentralSurfaces` / `ControlCenterControllerImpl` 类与方法在安装阶段解析；`KeyguardViewMediator` 类缓存；`mContext` `Field` 缓存；`isScreenLockDisabled` 通过 `getAdditionalStaticField` 读取。
- `mAfterUnlockReceiver`：`Dependency` / `ControlPanelController` / 控制面板链式字段与方法全部缓存；`Dependency.get` 改为 `Method.invoke`。

### 5.2 未改变（按约束保留）

- 不缓存 `QSTileHost`、`MiuiQSFactory`、Tile、Context、Handler、View、SystemUI 实例。
- 不新增通用反射缓存框架、无上限 Map/List、ThreadLocal 或对象池。
- 不合并 Hook call site、不扩大进程范围、不新增线程/监听器/Observer。
- 不修改 Secure QS 的功能语义：仍按偏好保护指定的 Tile。

## 6. 并发安全

- 所有解析阶段工作都在 `PackageReady` 单线程安装路径完成。
- 回调内只使用 `final` 不可变 `Field` / `Method` / `Class` 引用。
- `securedTiles` 仍为 `ArrayList<String>`，仅保存已保护的 Tile 类全名，不使用同步；SystemUI 主线程执行 Tile 创建，无并发问题。

## 7. 失败路径

- 若目标 ROM 缺失某个反射成员，解析阶段标记失败并跳过对应功能，不在回调中重复尝试。
- 若 `ControlCenterControllerImpl` 或 `CentralSurfaces` 在 MIUI/HyperOS 分支不存在，则 `findClassIfExists` 返回 null，回调中直接使用 null 走原分支。
- 若 `ControlPanelController` 或控制面板链式成员缺失，`usingCenter` 分支使用 null 安全返回。
- 若 callback 运行中遇到异常，继续抛出 `OutOfMemoryError` / `ThreadDeath` / `VirtualMachineError`，其他异常捕获并记录一次。
