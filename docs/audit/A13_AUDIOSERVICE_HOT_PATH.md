# A13 AudioService Hot-Path Cost Audit

> Branch: `devin/a13-memory-performance-optimization`
> Generated by: static analysis of `SystemAudioAndVolumeHooks.kt`, `FeatureCatalog.kt` and `CatalogContracts.kt`.

本文件记录 P1B-2 阶段对 `AudioService#createStreamStates` 与 `AudioService$VolumeStreamState#readSettings` 两个目标的调用链、修改前成本与优化后成本的证据。

P0 真实设备基线仍为 `RUNTIME_BASELINE_PENDING_DEVICE`，因此任何性能收益数字均为静态推断，不声称具体 KB、MB、百分比、延迟或耗电变化。

## 1. 目标与范围

- **createStreamStates**：仅在 `system_volumesteps > 0` 时安装，`before` 回调修改 `MAX_STREAM_VOLUME` 数组。
- **VolumeStreamState#readSettings**：仅在 `system_separatevolume` 为 `true` 时安装，`before` 回调为 `mStreamType == 1` 的流重建 `mIndexMap`。
- 不处理 `updateStreamVolumeAlias`、`shouldZenMuteStream`、音量 UI、Tile、通知菜单、Launcher、其他 AudioService 方法。

两个特征均为 `REBOOT` 生效，`ConfigReloadMode.NONE`，因此相关元数据在 `SYSTEM_SERVER_STARTING` 阶段一次性解析是安全的。

## 2. 修改前调用链

### 2.1 AudioService#createStreamStates

```
MainModule.onSystemServerStarting
  ├─ initPrefs()
  └─ SystemServerInstaller.install()
       └─ FeatureDispatcher.installById("volumeSteps", runtime)
            └─ SystemAudioAndVolumeHooks.VolumeStepsHook(lpparam)
                 └─ ModuleHelper.findAndHookMethod(
                        "com.android.server.audio.AudioService",
                        lpparam.classLoader,
                        "createStreamStates",
                        object : MethodHook() {
                            override fun before(param) {
                                1. XposedHelpers.findClass("com.android.server.audio.AudioService", ...)  // CALLBACK_TIME_REFLECTION
                                2. XposedHelpers.getStaticObjectField(audioCls, "MAX_STREAM_VOLUME")       // CALLBACK_TIME_REFLECTION
                                3. MainModule.mPrefs.getInt("system_volumesteps", 0)                       // IN_MEMORY_SNAPSHOT_READ
                                4. 若 mult <= 0，return
                                5. 循环修改 maxStreamVolume[i]
                                6. XposedHelpers.setStaticObjectField(audioCls, "MAX_STREAM_VOLUME", ...)  // 不必要，数组已在原地修改
                            }
                        })
```

### 2.2 AudioService$VolumeStreamState#readSettings

```
MainModule.onSystemServerStarting
  ├─ initPrefs()
  └─ SystemServerInstaller.install()
       └─ FeatureDispatcher.installById("notificationVolume", runtime)
            └─ SystemAudioAndVolumeHooks.NotificationVolumeServiceHook(lpparam)
                 └─ ModuleHelper.findAndHookMethod(
                        "com.android.server.audio.AudioService$VolumeStreamState",
                        lpparam.classLoader,
                        "readSettings",
                        object : MethodHook() {
                            override fun before(param) {
                                1. XposedHelpers.getIntField(param.thisObject, "mStreamType")
                                2. 若 mStreamType != 1，return
                                3. synchronized(param.member.declaringClass)
                                4. XposedHelpers.findClass("android.media.AudioSystem", ...)             // CALLBACK_TIME_REFLECTION
                                5. XposedHelpers.getStaticObjectField(audioSystem, "DEVICE_OUT_ALL_SET")  // CALLBACK_TIME_REFLECTION
                                6. XposedHelpers.getStaticIntField(audioSystem, "DEVICE_OUT_DEFAULT")     // CALLBACK_TIME_REFLECTION
                                7. XposedHelpers.getStaticObjectField(audioSystem, "DEFAULT_STREAM_VOLUME") // CALLBACK_TIME_REFLECTION
                                8. XposedHelpers.getObjectField(
                                       XposedHelpers.getSurroundingThis(param.thisObject), "mContentResolver")
                                9. XposedHelpers.getObjectField(param.thisObject, "mIndexMap")
                                10. for (deviceType in DEVICE_OUT_ALL) {
                                      XposedHelpers.callMethod(param.thisObject, "getSettingNameForDevice", deviceType)
                                      defaultValue 计算
                                      XposedHelpers.callStaticMethod(
                                          Settings.System::class.java,
                                          "getIntForUser",
                                          mContentResolver, name, defaultValue, -2)                     // DISK_OR_IPC_READ
                                      若 index != -1：
                                          XposedHelpers.callMethod(param.thisObject, "getValidIndex", 10 * index, true)
                                          mIndexMap.put(deviceType, validIndex)
                                    }
                                11. XposedHelpers.setObjectField(param.thisObject, "mIndexMap", mIndexMap)
                                12. param.returnAndSkip(null)
                            }
                        })
```

## 3. 优化策略（已实施）

### 3.1 稳定元数据提前解析

- `AudioService` / `AudioService$VolumeStreamState` / `android.media.AudioSystem` / `android.provider.Settings$System` 的 `Class` 在 `SYSTEM_SERVER_STARTING` 阶段解析。
- `MAX_STREAM_VOLUME`、`DEVICE_OUT_ALL_SET`、`DEVICE_OUT_DEFAULT`、`DEFAULT_STREAM_VOLUME`、`mStreamType`、`mIndexMap`、`mContentResolver`、`this$0`、`getSettingNameForDevice`、`getValidIndex`、`getIntForUser` 等 `Field` / `Method` 在注册阶段解析。
- 不持有 `AudioService` 或 `VolumeStreamState` 实例；仅持有 `java.lang.reflect.Field` / `Method` 与不可变常量（`Set<Integer>`、`IntArray`、primitive）。

### 3.2 回调内不变量

- `mult` 从 `MainModule.mPrefs` 提到 `VolumeStepsHook` 外部，callback 内只进行数组乘法。
- `DEVICE_OUT_ALL`、`DEVICE_OUT_DEFAULT`、`DEFAULT_STREAM_VOLUME` 提前解析，callback 内直接遍历/取值。
- `Settings.System.getIntForUser` 的 `Method` 与 `mContentResolver` 的 `Field` 提前解析，callback 内 `Method.invoke`。
- `synchronized` 使用 `VolumeStreamState.class` 对象，不再调用 `param.member.declaringClass`。

### 3.3 不允许的优化

- 不缓存 `AudioService` 实例、不缓存 `VolumeStreamState` 实例、不缓存 `Context` / `Handler` / `Binder`。
- 不新增通用反射缓存框架、无上限 Map/List、ThreadLocal 或对象池。
- 不合并 Hook call site、不扩大进程范围、不新增线程/监听器/Observer。
- 不替换 `Settings.System.getIntForUser` 的语义；仍按设备读取系统设置。

## 4. 并发安全

- 所有解析阶段工作都在 `SYSTEM_SERVER_STARTING` 单线程安装路径完成。
- 回调内只使用 `final` 不可变 `Field` / `Method` 引用；这些方法/字段在解析后不可变。
- `readSettings` 仍对 `VolumeStreamState.class` 加锁，与修改前语义一致。

## 5. 失败路径

- 若目标 ROM 缺失某个反射成员，解析阶段标记为 `UNSUPPORTED`，直接跳过对应 Hook 安装，不在回调中重复尝试。
- 若 callback 运行中遇到异常，继续抛出 `OutOfMemoryError` / `ThreadDeath` / `VirtualMachineError`，其他异常捕获并记录一次（使用现有 `XposedHelpers.log`），避免高频重复日志。
- 不吞掉所有异常的空 catch。

## 6. 实现证据

- `SystemAudioAndVolumeHooks.kt` 中 `VolumeStepsHook` 在 `createStreamStates` Hook 安装阶段完成以下工作：
  - `AudioService` `Class`、`MAX_STREAM_VOLUME` `Field` 在注册时解析并缓存。
  - `mult = MainModule.mPrefs.getInt("system_volumesteps", 0)` 在注册阶段读取，callback 内部只执行数组乘法与赋值。
  - 移除了 `XposedHelpers.setStaticObjectField`，因为 `IntArray` 已在原地修改。

- `installNotificationVolumeReadSettingsHook` 在 `AudioService$VolumeStreamState#readSettings` 安装阶段完成以下工作：
  - `AudioService$VolumeStreamState`、`android.media.AudioSystem`、`android.provider.Settings$System` 以及所有需要的 `Field` / `Method` 在注册时解析。
  - `DEVICE_OUT_ALL_SET`、`DEVICE_OUT_DEFAULT`、`DEFAULT_STREAM_VOLUME`、`mContentResolver`、`mIndexMap`、`this$0`、`mStreamType`、`getSettingNameForDevice`、`getValidIndex`、`Settings.System.getIntForUser` 全部缓存。
  - callback 内不再调用 `XposedHelpers.findClass` / `getObjectField` / `callMethod` / `callStaticMethod`，仅使用缓存的 `Field.get` / `Method.invoke`。
  - `synchronized` 对象改为 `volumeStreamStateClass`，避免 `param.member.declaringClass` 反射。

## 7. 测试验证

- 新增 `AudioServiceHotPathCallbackTest.kt` 覆盖两个热路径回调：
  - `volumeStepsHook_modifiesMaxStreamVolume`：验证 `createStreamStates` `before` 回调按 `system_volumesteps=150` 修改 `MAX_STREAM_VOLUME`。
  - `volumeStepsHook_doesNotInstallWhenPreferenceIsZero`：验证 `system_volumesteps=0` 时不安装 Hook。
  - `readSettingsHook_returnsEarly_forNonStreamType1`：验证 `mStreamType != 1` 时直接返回，不调用 `getSettingNameForDevice`。
  - `readSettingsHook_buildsIndexMap_forStreamType1`：验证 `mStreamType == 1` 时按 `AudioSystem.DEVICE_OUT_ALL_SET` 遍历并调用 `getValidIndex(50, true)`。
  - `readSettingsHook_keepsIndexMapEmpty_forMissingSettingsValue`：验证非默认设备 `def=-1` 时跳过，仅默认设备 `DEVICE_OUT_DEFAULT=2` 使用 `DEFAULT_STREAM_VOLUME` 计算。

- 新增 `ChildFirstClassLoader.kt` 用于在单元测试中隔离 fake `android.media.AudioSystem`、`android.provider.Settings`、`android.util.Log` 与真实 `android.jar` stub，保证 `AudioService` fake 类可被加载并测试反射热路径。
