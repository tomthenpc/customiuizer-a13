## 有效变更分组

### 1. 安装架构与进程路由 (`process-and-installer-routing`)

- **关键事实**：新增 `ProcessScope` 与 `ProcessScopes.resolve()` 作为包/进程路由唯一来源；`MainModule.onPackageReady()` 移除 `Application.attach` 与 `mPrefs.get*` 调用，改由 `ProcessScope` 分发到 `AndroidPackageInstaller` / `SystemUiInstaller` / `LauncherInstaller` / `SettingsInstaller` / `SecurityCenterInstaller` / `PowerKeeperInstaller` / `WallpaperInstaller` / `MediaInstaller` / `PhoneInstaller` / `PackageInstallerRouter` / `InputMethodInstaller` / `GenericAppInstaller` 等独立 Installer。
- **用户影响**：模块仅在已知/可安装进程中加载，避免非目标进程初始化；各 Installer 职责更清晰。
- **最终证据**：`ProcessScope.kt:10-38`（enum + `isInstallable`），`ProcessScope.kt:89-135`（`resolve` / `shouldLoadPrefs` / `shouldHook`），`MainModule.java:88-166`（按 scope 分发），`installers/*.java`（新增/修改 13 个）。
- **测试**：`test_process_scope.py`、`test_process_scope_table.py`、`test_main_module_routing.py`、单元测试。
- **置信度**：High

### 2. 特性目录与安装注册表 (`catalog-registry`)

- **关键事实**：新增 `FeatureCatalog`（静态类型化 `FeatureSpec` 目录）、`FeatureInstallRegistry`（进程级安装注册表，含 id 归一化、别名冲突检查、原子 `INSTALLING` 申领、兼容政策、状态诊断）、`CatalogContracts`、`FeatureDispatcher`、`InstallPhase` 等；大批功能迁移到注册表。
- **用户影响**：功能安装有统一状态机和失败隔离；缺少 ROM 目标时安全跳过；避免同一进程重复安装。
- **最终证据**：`FeatureCatalog.kt`（大量 `FeatureSpec`）、`FeatureInstallRegistry.kt:32-355`（register / installById / 原子 claim / 兼容检查）、`CatalogContracts.kt`、相关类型。
- **测试**：`FeatureInstallRegistryTest.kt`、`FeatureCatalogTest.kt`、`CatalogBatch1/2/3/9And10ContractTest.kt`、`FeatureIdentityCompletenessTest.kt`、Python 合同测试。
- **置信度**：High

### 3. ROM 兼容与 Hook 合同 (`rom-compatibility`)

- **关键事实**：新增 ROM 过程矩阵、Hook 合同、兼容性探测、`AnyOfRequirement` / `SingleTargetRequirement` 语义，resolver 与 installer 使用同一 resolved target；MIUI 14 为主基线，HyperOS 1 为实验目标，缺少目标时安全跳过，不跨候选混装。
- **用户影响**：MIUI 14 稳定性优先；HyperOS 1 不会误装不适用的 Hook；失败原因可追踪。
- **最终证据**：`RomEnvironmentDiagnostics.kt`、`HookTargetResolver.kt`、`CatalogContracts.kt`、`mods/utils/AnyOfRequirement.kt`、`SingleTargetRequirement.kt`、`HookTargetContract.kt`、`docs/rom-intelligence/A13_PROCESS_MATRIX.md`、工具脚本。
- **测试**：`test_check_hook_contract_parity.py`、`test_rom_intelligence.py`、合同测试。
- **置信度**：High (static)

### 4. 偏好早期加载 (`preference-loading`)

- **关键事实**：从 `MainModule` 提取 `PreferenceLoadRegistry`，集中处理 `various_alarmcompat`、`system_statusbarcolor`、`system_nooverscroll`、`controls_volumemedia` 四个遗留规则的加载判断，保持原 `||` 短路和异常语义。
- **用户影响**：只有被选中且开关打开的应用才加载偏好，减少非目标应用初始化。
- **最终证据**：`PreferenceLoadRegistry.kt:41-132`、`MainModule.java:99-100`。
- **测试**：`PreferenceLoadRegistryTest.kt`、`test_main_module_routing.py`。
- **置信度**：High

### 5. 致命错误透传 (`fatal-propagation`)

- **关键事实**：新增 `RuntimeFatality.throwIfFatal()` / `ReflectionFatality`；`ModuleHelper`、`HookerClassHelper`、`XposedHelpers`、诊断记录器、安全适配器、回调入口统一重新抛出 `OutOfMemoryError` / `ThreadDeath` / `VirtualMachineError`。
- **用户影响**：致命 JVM 错误不再被吞掉，避免 SystemUI/Launcher/system_server 进入不可恢复状态；普通异常仍被隔离。
- **最终证据**：`RuntimeFatality.kt:14-34`、`ModuleHelper.java:111-128`（`throwIfFatal`）及多处调用、`ModuleHelper.java:1070-1147`（`guarded` 回调）。
- **测试**：`RuntimeFatalityTest.kt`、`XposedHelpersFatalityTest.java`、多个 `test_module_helper_*.py` 等。
- **置信度**：High

### 6. 生命周期治理 (`lifecycle-governance`)

- **关键事实**：`ModuleHelper` 增加 `registerModuleReceiver` / `registerOwnedReceiver` 与 `unregister*` 完整生命周期，状态机（PENDING_REGISTER / ACTIVE / STALE / RELEASED / REGISTER_FAILED），per-key 替换与 stale 清理；`ActivitySelector` / `AppSelector` 用 `postDelayed` 替代 `Thread.sleep`；偏好 Observer 支持弱引用 owner。
- **用户影响**：避免 Receiver/Observer 泄漏或重复注册；UI 选择器不再阻塞主线程。
- **最终证据**：`ModuleHelper.java:700-939`（Receiver 注册/释放/状态机）、`ModuleHelper.java:600-668`（PreferenceObserver 分发）。
- **测试**：`test_module_helper_receiver_lifecycle_fatality.py` 等。
- **置信度**：High

### 7. Launcher 动画缩放快路径 (`launcher-anim-fastpath`)

- **关键事实**：`LauncherAnimationHooks` 使用 `ValueAnimator.getDurationScale()` 获取动画缩放，移除反射与 `Settings.System` Binder 调用。
- **用户影响**：动画 Hook 热路径分配与 Binder 开销降低。
- **最终证据**：`LauncherAnimationHooks.kt:21-65`。
- **测试**：`LauncherAnimationScaleTest.kt`、`test_launcher_animation_scale_fastpath.py`。
- **置信度**：High

### 8. HotSeats 手势状态缓存 (`hotseat-gesture-cache`)

- **关键事实**：新增 `HotSeatGestureState`，按 View 实例缓存 density、`ViewConfiguration` 与触摸状态；阈值只在状态变化时解析一次。
- **用户影响**：减少每个触摸事件中的 density 与 `ViewConfiguration` 重复读取。
- **最终证据**：`LauncherGestureHooks.kt:26-64`、`LauncherHotSeatGestureStateTest.kt`。
- **测试**：`LauncherHotSeatGestureStateTest.kt`、`test_launcher_gesture_state_cache.py`。
- **置信度**：High

### 9. FSG BaseRecents 类缓存 (`fsg-recents-cache`)

- **关键事实**：`LauncherGestureHooks.FSGesturesHook` 在安装期解析 `com.miui.home.recents.BaseRecentsImpl` 一次，后续 callback 复用 `baseRecentsClass`；新增 `REAL_FORCE_FSG_NAV_BAR` 跨 callback 状态。
- **用户影响**：FSG 手势 `findClass` 仅执行一次。
- **最终证据**：`LauncherGestureHooks.kt:251-290`、`A13_FSG_BASE_RECENTS_CALL_SCOPE.md`。
- **stack-scope 优化**：替换 `Thread.currentThread().stackTrace` 因缺少 ROM 输入被冻结，见 `A13_FSG_BASE_RECENTS_CALL_SCOPE.md`。
- **置信度**：Medium（静态+测试，无 ROM 验证）

### 10. DeviceInfo 低分配 sysfs 采样 (`deviceinfo-sampler`)

- **关键事实**：`DeviceInfoMonitor` 改用 `DeviceInfoSysfsParser`，使用 8 KiB / 64 B 固定缓冲区与逐字节解析；移除 `Properties`、`RandomAccessFile`、临时结果对象与周期性屏幕状态 Binder 查询。
- **用户影响**：状态栏设备信息刷新内存占用更低，Binder 调用更少。
- **最终证据**：`DeviceInfoSysfsParser.kt:1-145`、`DeviceInfoMonitor.kt:341+`（`sampleAndPublish`）、`DeviceInfoSysfsParserTest.kt`。
- **测试**：`DeviceInfoSysfsParserTest.kt`、`DeviceInfoMonitorLifecycleTest.kt`、`test_device_info_low_allocation_sampler.py`。
- **置信度**：High
