# A13 SystemUI / Launcher Startup Load Gating

> Branch: `devin/a13-memory-performance-optimization`
> Generated by: static analysis of `MainModule.java`, `SystemUiInstaller.java`, `LauncherInstaller.java`, `SystemUIStatusBarHooks.kt` and `FeatureCatalog.kt`.

本文件记录 P1B-1 阶段对 A13 SystemUI 和 Launcher 启动加载路径的门控设计。

## 1. 目标与范围

- 仅处理 `com.android.systemui` 与 `com.miui.home` 在 `PackageReady` 触发后的启动逻辑。
- 功能族全部关闭时，不再执行：
  - `SystemUiInstaller.install()` 中的 `findContext` / `onCreate` hook / `GlobalActions.setupStatusBar()` / `FeatureRuntime` 创建及后续 hook 安装。
  - `LauncherInstaller.installPackageReady()` / `installApplication()` / `Application#attach` hook。
  - `MainModule.watchPreferenceChange()` 的重复调用。
- 保持默认行为、偏好生效语义和 `ConfigReloadMode` 不变。
- 不引入新 hook、线程、handler、observer、缓存或依赖。

## 2. 调用链与门控点

### 2.1 SystemUI

```
MainModule.onPackageReady
  ├─ initPrefs()                    // 远程偏好 + listener，不可避免
  └─ if (SystemUiInstaller.hasAnySystemUiStartupFeature(mPrefs))
       └─ SystemUiInstaller.install()
            ├─ StatusBarHeightRes()  // 仅在 system_statusbarheight > 19 时生效
            ├─ NavbarHeightRes()     // 仅在 controls_navbarheight > 19 时生效
            └─ if (!hasAnySystemUiStartupFeature) return  // 新增门控
                 ├─ findContext / Settings.System.getLong
                 ├─ SystemUIApplication#onCreate hook
                 │    └─ setupStatusBar() / watchPreferences.run()
                 ├─ GlobalActions.setupStatusBar()
                 ├─ FeatureRuntime + FeatureDispatcher.installById
                 └─ 各功能分支 ...
```

### 2.2 Launcher

```
MainModule.onPackageReady
  ├─ initPrefs()
  └─ if (LauncherInstaller.hasAnyLauncherStartupFeature(mPrefs))
       ├─ LauncherInstaller.installPackageReady()
       │    └─ 各资源替换 / hook 分支 ...
       ├─ LauncherInstaller.installApplication()
       │    └─ Application#attach hook -> handleLoadLauncher()
       │         └─ FeatureRuntime + 各功能分支 ...
       └─ watchPreferenceChange()
```

## 4. 门控实现说明

- 新增 `SystemUiInstaller.hasAnySystemUiStartupFeature(PrefMap)` 与 `LauncherInstaller.hasAnyLauncherStartupFeature(PrefMap)`，为纯函数式布尔判定。
- `SystemUiInstaller` 额外提供 `private hasAnyGlobalAction(PrefMap)`，用于识别跨进程全局动作。
- `MainModule.onPackageReady` 在调用 installer 前先检查谓词；谓词为 false 时直接跳过 installer 与 `watchPreferenceChange()`。
- 谓词使用 `MainModule.mPrefs` 快照，不触发额外 IPC。
- 所有 `FeatureDispatcher` 无条件调用仍保留在原位置；当谓词为 false 时不会执行到这些代码，因此不会创建 `FeatureRuntime` 或初始化 `FeatureCatalog`。

## 5. 偏好即时生效语义

- `ConfigReloadMode.NONE` 的功能：启动时安装、运行时变更需重启。谓词仅在启动判断，语义一致。
- `statusBarClockTweak` 为 `ConfigReloadMode.PARTIAL`（`system_statusbar_clocktweak`/`system_cc_clocktweak`/`system_cc_hidedate`/`system_cc_dateformat`）；启用时仍通过 `onCreate` 回调调用 `watchPreferences.run()`，保留运行时更新能力。
- Launcher 当前所有 catalog 功能均为 `ConfigReloadMode.NONE`，因此 `watchPreferenceChange()` 在 Launcher 中可省略，但保留以满足未来扩展。

- 新增 `LauncherInstallerTest`：验证默认关闭、手势动作、包就绪资源、`folder_cols`、`closeOnLaunch` 等场景。

## 7. 风险与后续

- `hasAny` 谓词与真实分支条件保持同步是关键；新增 SystemUI/Launcher 启动分支时，必须同步更新对应谓词或使其条件仍被现有谓词覆盖。
- 性能收益需实机测量；静态分析仅证明代码路径被门控。
